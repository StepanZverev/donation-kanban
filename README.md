# Donation Kanban

Менеджер донатов для стримеров и модераторов: донаты из DonationAlerts превращаются в карточки на канбан-доске.

- `frontend/` — React + TypeScript (Vite)
- `backend/` — Python, FastAPI, база данных PostgreSQL

## Запуск в режиме разработки

Понадобятся Node.js 20+, Python 3.11+ и [Docker Desktop](https://www.docker.com/products/docker-desktop/)
(в нём работает база данных).

**База данных** (PostgreSQL на порту 5432). Запусти Docker Desktop, потом из корня проекта:

```bash
docker compose up -d
```

Это нужно сделать один раз: дальше база запускается сама вместе с Docker Desktop.
Остановить — `docker compose stop`, данные при этом сохраняются. Таблицы бэкенд создаёт сам
при запуске (см. «Миграции» ниже). Рядом создаётся отдельная база `donation_kanban_test` для тестов.

**Бэкенд** (http://localhost:8000, документация API на http://localhost:8000/docs):

macOS / Linux:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

Windows (PowerShell):

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

Если PowerShell пишет, что выполнение сценариев отключено, один раз выполни
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` и повтори активацию.
После активации в начале строки терминала появится `(.venv)`.

**Фронтенд** (http://127.0.0.1:5173), в отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Фронт пересылает запросы `/api/*` на бэкенд (см. `frontend/vite.config.ts`). Если на странице написано «Бэкенд: работает», всё связано правильно.

## Подключение DonationAlerts

1. Зайди на https://www.donationalerts.com/application/clients и создай приложение.
   В поле Redirect URL укажи `http://127.0.0.1:8000/api/auth/callback`
   (если форма не примет такой адрес, укажи `http://localhost:8000/api/auth/callback`).
2. Скопируй `backend/.env.example` в `backend/.env` и впиши туда `DA_CLIENT_ID` и `DA_CLIENT_SECRET`.
   `DA_REDIRECT_URI` должен в точности совпадать с адресом из шага 1.
   Файл `.env` в git не попадает, ключи никому не отправляй.
3. Перезапусти бэкенд, нажми на «Гость» в правом углу шапки и выбери «Подключить DonationAlerts». После входа в DonationAlerts тебя вернёт на доску.

   Важно: в адресе из шага 1 и в адресе, по которому ты открываешь фронт, должен быть один и тот же хост
   (`127.0.0.1` и `127.0.0.1`, или `localhost` и `localhost`). Браузер хранит cookie входа отдельно для каждого
   хоста, и если они разные, вход закончится ошибкой «Вход устарел или начат не отсюда».

Новые донаты сразу появятся в «В очереди». Если бэкенд был выключен, при запуске он доберёт донаты,
пришедшие за это время. Старые донаты, пришедшие до первого подключения, не загружаются.

## Тесты бэкенда

Нужна запущенная база (`docker compose up -d`). Тесты работают в отдельной базе
`donation_kanban_test` и очищают её перед каждым тестом, настоящие данные они не трогают.

```bash
cd backend
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pytest
```

## Версии

Текущая версия и список изменений лежат в `frontend/src/changelog.ts`: верхняя запись — текущая версия.
Её видно внизу меню аккаунта, а по клику открывается окно «Что нового». Новая возможность поднимает
среднюю цифру (`0.8.2` → `0.9.0`), исправление — последнюю (`0.9.0` → `0.9.1`). `1.0.0` — открытый запуск.

## Настройки по умолчанию

С какими колонками и уровнями приоритета создаётся доска, тексты вроде «Донат без сообщения»,
лимиты длины полей и задержки собраны в двух файлах: `backend/app/defaults.py` и
`frontend/src/defaults.ts`. Часть значений есть в обоих (они помечены); если они разойдутся,
упадёт тест `backend/tests/test_defaults.py`.

## Миграции

Таблицы базы описаны в `backend/migrations/` — по файлу на каждое изменение: `001_initial.sql`,
потом `002_….sql` и так далее. При запуске бэкенд выполняет по порядку файлы, которых в базе
ещё не было, и запоминает их в таблице `schema_migrations`. Чтобы поменять базу (добавить поле
или таблицу), создай новый файл со следующим номером. Уже выполненные файлы не меняй.

## Переезд со старой базы SQLite

До этапа 7 всё хранилось в файле `backend/donations.db`. Чтобы перенести оттуда доску,
карточки, настройки, подключение DonationAlerts и модераторов, один раз выполни
(база PostgreSQL должна быть запущена и пустая):

```powershell
cd backend
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m app.import_sqlite donations.db
```

Скрипт напишет, сколько строк перенёс. Входить заново не нужно: сессии тоже переносятся.
Файл `donations.db` скрипт не меняет, после проверки его можно удалить.

## API

Полный список с возможностью отправить запрос прямо из браузера: http://localhost:8000/docs

Всё, что относится к доске, лежит под `/api/boards/{board_id}/...`. Бэкенд по cookie сессии
проверяет, что у пользователя есть доступ к этой доске (он хозяин или модератор). На чужую доску
отвечает 404, а модератору на то, что может только хозяин, — 403.

| Метод и путь | Что делает |
|---|---|
| `GET /api/me` | кто открыл сайт, его доска (`board_id`) и доски, где он модератор. Первый запрос создаёт гостя и ставит cookie `session` |
| `POST /api/me/logout` | выйти на этом устройстве (гостю нельзя) |
| `GET /api/auth/status` | подключён ли DonationAlerts и что делает приёмник донатов |
| `GET /api/auth/login` | перейти на вход в DonationAlerts |
| `GET /api/auth/callback` | сюда DonationAlerts возвращает после входа |
| `POST /api/auth/logout` | отключить DonationAlerts |
| `GET /api/boards/{id}` | чья доска и кто на ней ты (`owner` или `moderator`) |
| `… /cards`, `… /columns`, `… /history` | карточки, колонки и история доски |
| `… /settings/...` | настройки доски; менять может только хозяин |
| `GET … /stream-total`, `POST … /reset` | сумма за стрим и «Сбросить доску» (только хозяин) |
| `GET … /donors` | подсказки ников донатеров |
| `POST … /dev/fake-donation` | выдуманный донат для проверки |
| `WS … /ws` | живые обновления: сервер шлёт `{"type": "board_changed"}`, когда доска меняется |
| `GET`/`DELETE … /members/{user_id}` | модераторы доски, убрать модератора (только хозяин) |
| `GET`/`POST`/`DELETE … /invite-link` | ссылка-приглашение: посмотреть, сделать новую, удалить вместе со всеми модераторами (только хозяин) |
| `GET /api/invites/{token}` | чья доска за приглашением |
| `POST /api/invites/{token}/accept` | принять приглашение и стать модератором |
| `… /settings/viewer`, `… /settings/viewer/link`, `… /settings/viewer/donation-url` | ссылка для зрителей и ссылка на донат (только хозяин) |
| `GET /api/public/boards/{token}` | доска для зрителей, без входа и только для чтения |
| `WS /api/public/boards/{token}/ws` | живые обновления доски для зрителей |

`…` — это `/api/boards/{id}`.

## Страница для зрителей

В «Настройки → Для зрителей» можно включить ссылку вида `/v/<токен>`. По ней любой без входа
видит твою доску только для чтения, и она обновляется сама. Если там же указать ссылку на донат,
у зрителей появится кнопка «+ Предложить задачу»: она откроет страницу доната, а донат сам станет
карточкой. Когда приём заказов закрыт, вместо кнопки зрители видят «Приём заказов закрыт».

## Модераторы

В «Настройки → Модераторы» можно сделать ссылку-приглашение. Кто её откроет и нажмёт «Принять»,
станет модератором: сможет двигать, править и убирать карточки на твоей доске. Настройки, колонки
и сброс доски остаются только у хозяина. Входить через DonationAlerts модератору не обязательно,
но без входа доступ живёт только в одном браузере. Список модераторов там же, любого можно убрать.
«Новая ссылка» заменяет старую, а модераторы остаются. «Удалить» убирает ссылку вместе со всеми модераторами.

Адреса доски на фронте: `/boards/<id>`, `/boards/<id>/history`, `/boards/<id>/settings/...`.
Адрес `/` открывает твою доску, а чужие доски, где ты модератор, есть в меню аккаунта справа.

## Гости и вход

Регистрации нет. При первом открытии сайта бэкенд создаёт пользователя-гостя и запоминает браузер
по cookie. Подключение DonationAlerts закрепляет гостя за аккаунтом DA: на другом устройстве можно
войти через DonationAlerts и попасть в того же пользователя. Кто вошёл, видно в правом углу шапки.

У каждого пользователя своя доска: свои колонки, карточки, история и настройки. Донаты из
DonationAlerts падают на доску того, кто подключил DonationAlerts. Подключение тоже у каждого своё:
DonationAlerts могут подключить несколько стримеров сразу, бэкенд слушает донаты каждого отдельно,
а «Отключить» отключает только твой DonationAlerts.
